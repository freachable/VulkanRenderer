# Map data format (version 1)

> p1_001 (GitHub issue #5). Draft by P1, to be agreed with the team (P3 places foliage from `foliage.json`, P4's camera uses the world scale).

A map is a directory with five files, read by `loadMapData` in `src/map/MapData.hpp`.

```
assets/maps/<name>/
  map.json         manifest
  heightmap.png    terrain heights
  albedo.png       top-down map texture
  buildings.json   building footprints
  foliage.json     green areas
```

Produce one with:

- `python tools/generate_sample_map.py`: synthetic map, standard library only (`assets/maps/sample` is generated by it)
- `python tools/osm_export.py --bbox W S E N --out assets/maps/<name> [--dem dem.tif]`: real OpenStreetMap data (`pip install -r tools/requirements.txt`)

## World space

- Units are meters. **x points east, y up, z south** (right-handed).
- The map is centered on the origin: x in `[-size[0]/2, size[0]/2]`, z in `[-size[1]/2, size[1]/2]`.
- 2D points are written as `[x, z]`.
- Both images cover exactly the map area. Image row 0 is the **northern** edge (z = -size[1]/2), column 0 the western edge.
  Texture coordinates: `u = (x + size[0]/2) / size[0]`, `v = (z + size[1]/2) / size[1]`.

## map.json

```json
{
  "version": 1,
  "name": "sample",
  "size": [1024.0, 1024.0],
  "heightRange": [4.0, 75.0],
  "heightmap": "heightmap.png",
  "albedo": "albedo.png",
  "buildings": "buildings.json",
  "foliage": "foliage.json"
}
```

| Field | Meaning |
|---|---|
| `version` | Format version, currently 1. Readers reject other versions; bump it on incompatible changes |
| `name` | Optional, defaults to the folder name |
| `size` | Map extent in meters along x and z |
| `heightRange` | Heights in meters for heightmap value 0 and 65535 |
| `buildings`, `foliage` | Optional |

## heightmap.png

Grayscale PNG, preferably 16-bit (8-bit works but is coarse). `height = heightRange[0] + value / 65535 * (heightRange[1] - heightRange[0])`. Any size of at least 2x2; the renderer resamples it to at most 513x513 vertices.

## albedo.png

RGB(A) PNG/JPG in sRGB, any size. Sampled with clamp-to-edge.

## buildings.json

```json
{ "buildings": [
  { "footprint": [[x, z], ...], "triangles": [0, 1, 2, ...], "height": 18.5, "color": [0.7, 0.7, 0.72] }
] }
```

| Field | Meaning |
|---|---|
| `footprint` | Outline, at least 3 points, either orientation, no repeated closing point, no holes |
| `triangles` | Optional flat index list into `footprint`. Concave outlines need it; without it the outline is fan-triangulated (convex only). Winding does not matter |
| `height` | Meters above the lowest terrain point under the footprint |
| `color` | Optional sRGB in [0, 1] |

Walls are generated for every triangle edge used by exactly one triangle (the outline).

## foliage.json

```json
{ "areas": [ { "type": "park", "polygon": [[x, z], ...] } ] }
```

`polygon` is a simple outline in world (x, z). `type` is informational (`park`, `forest`, `grass`, ...).

## Open questions

2. **Foliage (P3):** are polygons enough, or do you need individual positions (e.g. points scattered per area)?
